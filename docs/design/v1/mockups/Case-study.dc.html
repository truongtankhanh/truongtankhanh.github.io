Overview

The demo runs on a fictional campus with synthetic incidents and simulated cameras. The engineering is what a real control room needs: a live feed that never disagrees between screens, a response workflow where every action is recorded, and a stack that comes up with one command.

What it does

1 sfor a new report to reach every open console

Live incident feed

New reports reach every open console within a second, ordered by what needs attention first: unresolved, then severity, then age.

Cameras in context

The cameras covering an incident’s zone come first, behind a source-agnostic stream descriptor so mock feeds and real streams switch by configuration.

Respond and record

Acknowledge or resolve with a note. Every change is written to the incident timeline and invalid transitions are rejected by the server.

Map, 3D twin and video wall

A site plan that works offline, a three.js view of the campus where WebGL 2 is available, and a read-only control-room screen.

Decisions that shaped it

Each one is a written decision record with the options that were rejected.

How to check it

Open the console in two browser windows and acknowledge an incident in one: it updates in the other within a second, even when the two windows are on different API replicas. The incident lifecycle is enforced by the domain, and the end-to-end tests run against a real PostgreSQL.

Run it

One command brings up the whole stack. The demo accounts are listed in the repository README.

pnpm docker:stack
# Console     http://localhost:18080
# API + docs  http://localhost:18080/api/docs
